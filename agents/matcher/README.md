# Matcher Agent (`agents/matcher/`)

**Owner:** Backend 3  
**Responsibility:** Score opportunities against company profiles and produce ranked `Recommendation` objects.

---

## What it does

Given a `CompanyProfile` (a list of `Claim` objects) and a list of `Opportunity` objects, the matcher returns a ranked list of `Recommendation` objects, one per matched opportunity, sorted by descending score.

### Scoring formula

```
score = 0.50 × topic_overlap
      + 0.30 × timeline_score
      + 0.20 × location_format_score
```

Weights are in [`config.py`](config.py) and can be changed without touching `matcher.py`.

| Dimension | How it works |
|---|---|
| **Topic overlap** | Jaccard-style overlap between opportunity topics and profile claim values across fields: `technologies`, `expertise`, `topics`, `products_services`, `application_areas`, `markets`, `industries`, `priorities`, `projects`. `user_confirmed` claims receive a **1.5× boost**, making them visibly affect the ranking. |
| **Timeline** | Full score (1.0) if deadline/event date ≤ 30 days away; linear decay to 0 at 365 days; 0.1 for expired; 0.5 if no date. |
| **Location / format** | Online opportunities score 1.0 (universally accessible). In-person: checks if the audience/eligibility text mentions the company's stated geographic focus. |

### `why` field

Generated by an LLM if `MATCHER_API_KEY` is set (reads `MATCHER_MODEL`, `MATCHER_API_KEY`, `MATCHER_BASE_URL` from env). Falls back to a deterministic sentence that references the actual `matched_claims`. The prompt lives in [`prompts/why_v1.md`](prompts/why_v1.md).

## Environment variables

| Variable | Required | Description |
|---|---|---|
| `MATCHER_MODEL` | No | Model name (default: `openai/gpt-4o-mini`) |
| `MATCHER_API_KEY` | No | API key; if unset, deterministic `why` is used |
| `MATCHER_BASE_URL` | No | Base URL (default: `https://openrouter.ai/api/v1`; Ollama example: `http://ollama:11434/v1`) |
| Request timeout | — | Fixed at 5 seconds so claim edits fall back quickly if the provider is slow |

---

## Contract compliance

All output is validated against `contracts/recommendation.json` before being returned. The models in `models.py` mirror `contracts/claim.json`, `contracts/opportunity.json` and `contracts/recommendation.json`. If they ever diverge, `contracts/` wins.

**`user_confirmed` claims are never overwritten** — the matcher reads them but does not write to the profile.

## Demo requirement

> Two companies with different profiles get visibly different rankings.

This is verified by `TestDifferentProfilesDifferentRankings` in the test suite. The test asserts:
- An IoT company scores higher on an IoT funding call than a biotech company.
- A biotech company scores higher on a life science event than an IoT company.
- Adding a `user_confirmed` priority that matches the opportunity visibly raises the score.
